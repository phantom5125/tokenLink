# TokenLink 0.2.3 — Codex cost-estimate parity

This change aligns Codex local API-equivalent estimates with the request-level
method used by leading community usage tools while keeping OpenAI's first-party
pricing page as the price authority.

## Calculation changes

- Prefer `last_token_usage` for each request; use positive cumulative deltas
  only when the per-request counter is absent.
- Split inclusive Codex input into mutually exclusive buckets:
  `uncached = input - cache read - cache write`.
- Keep reasoning output inside `output_tokens`; do not charge it a second time.
- Attribute recorded `priority` / `fast` service tiers and apply the catalog's
  reviewed Fast multiplier before aggregation.
- For unmarked or unsupported speed records, use the non-secret top-level
  `service_tier` in `.codex/config.toml`, then fall back to Standard.
- Apply long-context pricing at request level, before daily, weekly, monthly,
  or per-model totals are assembled.
- Stream rollout files up to 256 MiB so normal long-running Codex sessions are
  not omitted by the previous 50 MiB guardrail; larger files remain excluded
  with a visible partial-scan warning.
- Exclude unknown models or incomplete price definitions instead of silently
  treating them as free.

## Price catalog

Catalog `2026-08-31.1` adds the current GPT-5.6 Codex family:

- `gpt-5.6-sol` (including the `gpt-5.6` alias)
- `gpt-5.6-terra`
- `gpt-5.6-luna`

Each entry carries separate standard prices for input, cached input, cache
writes, and output, plus the official long-context and Fast multipliers.
TokenLink continues to label these values **Estimated/API-equivalent**; they are
not a reconstruction of a ChatGPT or Codex subscription invoice.

The Mac packager now includes and verifies the Providers resource bundle, so
the reviewed catalog used by source tests is also present in installed builds.
