# TokenLink 0.2.2 Bluetooth diagnostics

This independent development branch adds user-visible StopWatch connection
diagnostics. It is intended to merge into `codex/release-v0.2.2` only after the
v0.2.1 physical reconnect check passes.

## User-visible behavior

- Opening StopWatch does not initialize CoreBluetooth or trigger permission.
- Pressing **Scan** or **Sync watch now** remains the explicit action that may
  initialize Bluetooth and display the macOS nearby-device request.
- The new checklist distinguishes permission, adapter, binding, connection,
  C04 command subscription, and payload sync instead of collapsing every
  failure into “Disconnected.”
- Recovery guidance links permission failures to **System Settings → Privacy &
  Security → Bluetooth** and describes what to retry for timeouts or firmware
  compatibility failures.

## Privacy boundary

The checklist and exported diagnostic fields contain state names and booleans.
They do not contain provider credentials, token counts, API payloads, watch
payload contents, or a device UUID. The existing diagnostic exporter still
applies its final redaction pass.

## Acceptance

1. With Bluetooth permission undecided, open StopWatch and confirm no macOS
   prompt appears until **Scan** or **Sync watch now** is pressed.
2. Deny Bluetooth once and confirm the permission row gives the exact System
   Settings recovery path.
3. Allow Bluetooth, bind the C152, and sync protocol v2. Permission, adapter,
   connection, and C04 command-channel rows should all become green.
4. Turn the watch off and retry. The connection and last-failure rows should
   explain the timeout/disconnect without exposing identifiers.
5. Export diagnostics and verify the `bluetooth` object contains only redacted
   state-machine fields.
