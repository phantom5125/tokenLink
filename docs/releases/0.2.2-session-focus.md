# TokenLink 0.2.2 Session focus feedback

This independent development branch improves the reliability and
explainability of protocol-v2 Session focus. It is intended to merge into
`codex/release-v0.2.2` after the v0.2.1 C04 subscription fix is physically
verified.

## What changed

- TokenLink still uses the task URL emitted by Codex, in the form
  `codex://threads/<id>`.
- The link is now delivered to the currently running Codex application bundle
  explicitly with activation enabled. A generic `NSWorkspace.open` success is
  no longer treated as sufficient evidence.
- Every Codex row in the StopWatch settings has an arrow button that exercises
  the exact same slot-to-task mapping without Bluetooth.
- TokenLink shows whether the link was delivered, only the app was activated,
  the slot had expired, the provider was unsupported, or Codex was unavailable.
- Logs and UI outcomes never include the task identifier.

The macOS API confirms delivery to the target application, not the final
selected view inside Codex. The UI therefore says “task link was delivered”
instead of claiming an unverifiable focus success.

## Acceptance sequence

1. In TokenLink, refresh until the current Codex task appears in the work-item
   list.
2. Click that row's arrow button. Confirm Codex comes forward on the matching
   task and TokenLink reports that the link was delivered.
3. With the protocol-v2 C152 connected and C04 subscribed, select the same item
   on the watch. Confirm the same result appears below the list.
4. Quit Codex and retry. TokenLink should report that Codex is unavailable,
   without exposing the task ID.
5. Leave a stale watch page open, remove or replace its task in TokenLink, then
   select it. TokenLink should report that the watch slot no longer maps to a
   current task.
