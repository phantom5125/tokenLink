# TokenLink 0.2.1

TokenLink 0.2.1 makes the M5Stack StopWatch C152 experience reproducible from a
single repository. The Mac app, BLE protocol v1/v2 implementation, four-page
firmware UI, tests, release packaging, and documentation now ship together.

## Highlights

- Build the complete default wireless C152 firmware from this TokenLink tag;
  no companion checkout or submodule is required.
- Retains the firmware subtree's MIT license, notices, and Space Mono OFL while
  keeping TokenLink's Mac/shared source under Apache-2.0.
- Pins PlatformIO, ESP32 platform, M5Stack libraries, ArduinoJson, partition
  layout, and the M5GFX C152 power patch used by the verified firmware line.
- Runs ten host-native gesture, power, model, payload, and protocol-v2 tests in
  addition to the real ESP32-S3 build.
- Publishes a merged image for manual flashing, a complete split-image archive,
  SHA-256 checksums, and machine-readable manifests for future local installers.
- Keeps the v0.2 Home, Quota, Sessions, and System UI, matching Mac/watch quota
  bars, aggregate active Codex count, and session-to-Mac focus command.
- Shows the protocol-v2 four-page face immediately at boot. Only a successfully
  parsed v1 payload opts the current connection into the legacy dashboard.
- Leaves Claude disabled on new installs and accesses `Claude Code-credentials`
  only after the user enables Claude, reviews the macOS authorization scope, and
  explicitly continues.
- Uses the `TokenLink` app identity and `app.tokenlink.provider` Keychain service.
  Upgrades do not read the previous service automatically; the Providers screen
  offers a one-time, explained migration for existing TokenLink provider keys.
- Treats the bundle-identifier change as a Bluetooth identity migration: an old
  peripheral UUID is cleared, the StopWatch page explains the authorization
  scope, and the user explicitly scans and binds once under `app.tokenlink`.
- Does not report a protocol-v2 StopWatch connection as ready until CoreBluetooth
  confirms the C04 watch-command notification subscription.
- Passes 177 Swift tests plus ten host-native firmware test executables before
  the final physical-device release gates.

## Assets

- `TokenLink-0.2.1-macos-<architecture>.zip` and `.sha256`: the filename states
  the CI runner architecture. It is an ad-hoc-signed development build, not
  Developer ID signed or notarized.
- `TokenLink-StopWatch-C152-0.2.1.bin`: combined ESP32-S3 image for M5Stack
  StopWatch Dev Kit C152 only; flash at offset `0x0` after resolving and
  confirming the exact serial port.
- `TokenLink-StopWatch-C152-0.2.1.zip`: split flash inputs, ELF, partition table,
  licenses, and per-image manifest for installers and diagnostics.
- `firmware-manifest.json` and `SHA256SUMS`: product/protocol metadata and
  integrity values for all firmware assets.

The Git tag contains the exact source for every asset, including
`firmware/stopwatch-c152`. A separate firmware source archive is no longer
needed.

## Install and safety notes

- Mac-only users can clone this tag and run `bash scripts/package_app.sh`.
- Source builders can run `bash scripts/test_firmware.sh` followed by
  `bash scripts/build_firmware_artifact.sh` after installing PlatformIO 6.1.19.
- Do not flash the C152 image to another M5Stack model. Read the repository Quick
  Start and M5Stack factory-recovery guide, identify the newly connected
  Espressif `/dev/cu.*` port, and confirm that exact port immediately before the
  upload.
- After flashing, verify `CODEX_MICRO_STOPWATCH_READY`, bind the explicit device
  in TokenLink, and verify protocol-v2 sync plus physical interaction separately.

## Known limitations

- The attached Mac archive is an architecture-specific, ad-hoc-signed
  development artifact. Building from source remains the supported path until a
  Developer ID-signed, notarized build is available.
- The new `app.tokenlink` bundle identity requires a one-time StopWatch rebind
  and can require new Bluetooth authorization and launch-at-login approval when
  upgrading from 0.2.0.
- A successful build, serial marker, or BLE sync does not establish a 24-hour
  sleep/wake/battery soak. Long-duration power behavior remains experimental.
