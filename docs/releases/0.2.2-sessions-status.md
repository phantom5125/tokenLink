# TokenLink 0.2.2 Sessions status clarity

This independent development branch makes the three-row Sessions page a
deliberate glance surface instead of implying that TokenLink can see only three
Codex tasks. It is intended to merge into the v0.2.2 release after review.

## User-visible behavior

- Sessions keeps three rows because that is the readable density for the C152
  round display. The header now separates the full active count from the number
  shown, for example `7 ACTIVE / 3 SHOWN`.
- Candidate selection is action-oriented: needs input, failed, running,
  completed, then unknown. Recency breaks ties, and rows that remain visible
  keep their existing focus slot.
- Running uses a small blue orbital animation. Needs input uses an amber pulse.
  Complete is a static green check, and failed is a static red alert. Every
  state also retains a text label, so color is not the only signal.
- The Sessions page redraws at 250 ms only while it is visible and the display
  is awake. No animation changes BLE traffic or keeps a sleeping display awake.

## Complete active count

TokenLink now follows the official Codex App Server `thread/list` cursor until
`nextCursor` is empty and requests `updated_at` ordering. Threads repeated while
pages are changing are deduplicated by ID, with the newest snapshot winning.
A repeated cursor or the 20-page safety cap fails the refresh and preserves the
last known store rather than labeling a partial count as complete.
After a complete successful refresh, sessions no longer returned by Codex are
removed; a failed or partial refresh leaves the last known rows untouched.

This behavior follows the official
[Codex App Server pagination contract](https://learn.chatgpt.com/docs/app-server#list-threads-with-pagination--filters).
The watch payload remains protocol v2 with three work-item slots, so existing
focus commands and payload-size limits are unchanged.

## Automated evidence

- 182 Swift tests pass, including multi-page thread aggregation, duplicate
  suppression, status priority, stable slot replacement, and payload limits.
- The real `m5stack-stopwatch` ESP32-S3 target builds successfully and eleven
  host-native firmware test executables pass.
- The 466 x 466 native preview renders normal and failed Sessions variants
  without round-display clipping or overlap with the focus action.
- The repository privacy scan passes.

## Physical acceptance still required

No device was flashed from this branch. Before release, verify on a physical
M5Stack StopWatch Dev Kit C152:

1. Running orbit and needs-input pulse remain legible at active and dimmed
   brightness without visible flicker.
2. Complete and failed icons remain distinguishable without relying on color.
3. `N ACTIVE / 3 SHOWN` agrees with a Mac that has more than three active Codex
   tasks.
4. Selecting each retained row still opens the matching Mac task after a
   higher-priority session replaces another slot.
5. Sessions animation does not regress desk sleep, wake, or expected battery
   behavior during the existing soak checklist.
