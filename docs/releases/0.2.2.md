# TokenLink 0.2.2

TokenLink 0.2.2 is a focused post-release stability update for StopWatch
diagnostics and Codex Sessions. It keeps the 0.2.1 credential, bundle identity,
BLE protocol v1/v2, and release-packaging boundaries unchanged.

## Highlights

- Adds a credential-free connection checklist that distinguishes Bluetooth
  permission, adapter state, binding, connection progress, C04 notifications,
  last sync, and the last redacted failure category.
- Keeps Bluetooth initialization explicit: opening StopWatch does not request
  permission; Scan or Sync watch now is the action that can initialize
  CoreBluetooth and show the macOS request.
- Delivers `codex://threads/<id>` links to the installed Codex application
  explicitly, exposes the same slot mapping as a Mac-side test button, and
  reports delivered, fallback, expired-slot, unsupported-provider, and
  unavailable outcomes without logging a task identifier.
- Pages through the complete official Codex App Server `thread/list` result in
  `updated_at` order, deduplicates moving threads by ID, rejects incomplete
  pagination, and removes sessions only after a complete successful refresh.
- Keeps three stable focus slots while prioritizing needs-input, failed,
  running, completed, and unknown sessions; the full active count remains
  independent of the three displayed rows.
- Shows `N ACTIVE / M SHOWN` on the C152 Sessions page. Running, needs-input,
  complete, and failed use distinct shapes, labels, colors, and motion policies
  so color is not the only status signal.
- Passes the combined 188-test Swift suite. The C152 release build and eleven
  host-native firmware test executables are part of the release gate.

## Assets

- `TokenLink-0.2.2-macos-<architecture>.zip` and `.sha256`: the filename states
  the CI runner architecture. Unless a Developer ID identity and notarization
  profile are supplied, this is an ad-hoc-signed development artifact, not a
  notarized default download.
- `TokenLink-StopWatch-C152-0.2.2.bin`: combined ESP32-S3 image for the M5Stack
  StopWatch Dev Kit C152; flash at offset `0x0` only after confirming the exact
  device port.
- `TokenLink-StopWatch-C152-0.2.2.zip`: split flash inputs, ELF, partition table,
  licenses, and image manifest.
- `firmware-manifest.json` and `SHA256SUMS`: product/protocol metadata and
  integrity values for every firmware asset.

The firmware remains protocol-v1/v2 compatible and declares TokenLink 0.2.1 as
its minimum host version. Use TokenLink 0.2.2 to receive the new diagnostics,
complete session pagination, and explicit focus feedback.

## Acceptance boundary

Automated checks cover parsing, pagination, slot priority, focus routing,
redaction, Bluetooth state projection, protocol payload limits, real ESP32-S3
compilation, firmware presentation helpers, and artifact checksums. Before
publishing the tag, complete the physical C152 checklist in the v0.2.2
validation report: connection-diagnostic state transitions, Mac and watch focus,
status animation/legibility, aggregate count, reconnect, sleep/wake, and a fresh
serial marker after flashing the exact release commit.

## Known limitations

- The three visible Sessions rows are intentionally a priority view, not the
  complete history. `N ACTIVE` is the complete active count.
- A successful macOS URL delivery means the link was delivered to Codex; the
  matching visible task still requires user-observed acceptance.
- The Mac archive remains architecture-specific and ad-hoc signed until a
  Developer ID-signed, Apple-notarized artifact is built and verified.
- Long-duration C152 battery and sleep/wake behavior remains experimental.
