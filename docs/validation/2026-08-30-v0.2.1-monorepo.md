# TokenLink v0.2.1 Monorepo Validation — 2026-08-30

This report covers the migration of the default wireless M5Stack StopWatch C152
firmware into TokenLink. Automated evidence and physical-device evidence remain
separate; pending rows are updated only after the corresponding observation.

## Results

| Layer | Evidence | Status | Limitations |
| --- | --- | --- | --- |
| Independent source boundary | The firmware project, partition table, simulator tests, font/license files, and build hooks live under `firmware/stopwatch-c152`; repository search found no build-time path or submodule dependency on an external firmware checkout. | PASS | Third-party PlatformIO packages are downloaded from their pinned upstream sources. |
| Cold PlatformIO build | PlatformIO Core 6.1.19 used a fresh repository-local core directory to install Espressif32 6.12.0, the pinned M5Stack revisions, and ArduinoJson 6.21.6, then built the ESP32-S3 image. RAM was 56,120 / 327,680 bytes (17.1%); flash was 1,330,521 / 6,553,600 bytes (20.3%). | PASS | Compilation is not a physical-device observation. |
| Firmware model/protocol tests | All nine native test executables passed: gestures, completion banner, power button, connection health, quota payload, host RPC, protocol v2, watch model, and raise-to-wake. | PASS | Host-native tests do not exercise the AMOLED, BLE radio, or PM1 hardware. |
| Release packager | The packager unit tests passed and generated a merged image, split-image ZIP, product/image manifests, and `SHA256SUMS`; every generated checksum verified. | PASS | Integrity is not code signing or hardware compatibility proof. |
| C152 flash and serial boot | After explicit confirmation of `/dev/cu.usbmodem101` (Espressif `303A:1001`, serial ending `0B:E4`), PlatformIO wrote bootloader, partition table, boot-app selector, and the 1,330,880-byte application; esptool verified every hash. The reset probe observed BLE v2/HID/GATT identity and `CODEX_MICRO_STOPWATCH_READY`. | PASS | Serial boot evidence does not prove pixels, gestures, or long-duration power behavior. |
| Installed Mac app | The verified ad-hoc archive replaced 0.2.0 under `/Applications`; TokenLink 0.2.1 build 3 launched successfully. | PASS | This local artifact is arm64, ad-hoc signed, and not notarized. |
| BLE protocol v2 and live sync | The fresh firmware paired with the installed app. Serial evidence recorded Codex (one window, three work items), Kimi (two windows, three work items), and MiniMax (two windows, three work items) v2 updates. | PASS | Claude and GLM were not selected in this live payload. |
| Physical UI regression | Inspect Home, Quota, Sessions, and System; verify Home-to-Sessions and session-to-Mac focus using the physical panel. | PENDING | Cannot be inferred from serial or BLE logs. |
| Long-duration power behavior | Complete a 24-hour sleep, wake, charging, and reconnect soak. | NOT VERIFIED | Out of scope for the migration release gate. |

## Release decision

The single-repository source/build/package path is automated and reproducible,
and the explicit C152 flash, boot, and live v2 sync regression passed. The v0.2.1
tag and release remain blocked on the physical UI regression, final hosted CI,
and TokenLink-only review/merge flow.
